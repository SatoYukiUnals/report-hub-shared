# report-hub をセットアップする（CLAUDE.md へ運用ルールを入れる）

report-hub は clone して起動しただけでは効かない。**AI が読む CLAUDE.md に運用ルールが入って、はじめてその通りに動く**。
このスキルはそのルールを、ユーザーが選んだ階層の CLAUDE.md へ書き込む。

ルールの本体は `rules/report-hub.md`（このリポジトリ内）。**CLAUDE.md にはその本体を読み込む数行だけを書く**ので、
ルールを直したときに配った先の CLAUDE.md を書き換えて回らずに済む（受け取った側は `git pull` するだけ）。
ルールそのものを直したいときは `rules/report-hub.md` を直す。CLAUDE.md 側の区画を手で直しても、次のセットアップで上書きされる。

## 1. どの階層の CLAUDE.md に入れるかを聞く

**勝手に決めない。** CLAUDE.md は下の階層ほど狭くしか効かないので、どこまで効かせたいかは使う人しか決められない。
候補を出して選んでもらう（AskUserQuestion を使う）。候補はこの 3 つを軸に、いまいる場所から組み立てる。

| 候補 | 効く範囲 |
| :--- | :--- |
| `~/.claude` | このマシンの全プロジェクト |
| リポジトリを束ねているディレクトリ（例 `~/ghq/github.com/<org>`） | その配下のリポジトリすべて |
| いまのリポジトリのルート（`git rev-parse --show-toplevel`） | このリポジトリだけ |

候補を出す前に、いまいる場所と親の階層に CLAUDE.md があるかを見ておくと選びやすい。

```bash
git rev-parse --show-toplevel 2>/dev/null
ls ~/.claude/CLAUDE.md 2>/dev/null
```

ユーザーが自分でパスを書いたときは、それをそのまま `--target` に渡す（ディレクトリでも `CLAUDE.md` そのものでもよい）。

## 2. 何が書き込まれるか見せる

```bash
python3 <report-hub>/bin/setup-claudemd.py status --target <選んだ階層>
```

- 書き込む元・書き込む先、パスの読み替え（`~/report-hub` → このマシンでの実際の場所）、差分が出る。
- 「差分なし」なら既に入っている。**何もしないで終える**（作業したように書かない）。
- 既にその CLAUDE.md に別のルールがあるときは、`<!-- report-hub:begin -->` 〜 `<!-- report-hub:end -->` の区画だけが入れ替わる。区画外は触らない。

### 書き方（既定は link のままでよい）

| モード | 書き込まれるもの | 使いどころ |
| :--- | :--- | :--- |
| `link`（既定） | 本体を読み込む数行 | ふつうはこちら。ルールの更新が `git pull` だけで届く |
| `--mode embed` | ルール本文をそのまま | 読み込み（`@` 記法）に対応していない道具で使うとき。更新のたびに入れ直しが要る |

**embed はユーザーが望んだときだけ使う。** 勝手に選ぶと更新のたびに全マシンを回ることになる。

## 3. 承認を得てから書き込む

差分をユーザーへ見せ、**承認を得てから**実行する。CLAUDE.md は以後そこ配下の全作業に効くので、黙って書き換えない。

```bash
python3 <report-hub>/bin/setup-claudemd.py apply --target <選んだ階層> --yes
```

- 既存ファイルは `CLAUDE.md.bak-<日時>` に控えが残る。
- 効くのは**次にセッションを開いたとき**から。いまの会話には自動では読み込まれない。これは必ず伝える。

## 4. レポートを出せる状態か確かめて伝える

ルールを入れただけでは閲覧できない。次を確認し、足りないものをユーザーへ伝える。

```bash
curl -s -o /dev/null -w '%{http_code}\n' --max-time 2 http://localhost:5180/
```

- 返らなければ**自分で起動する**（`cd <report-hub> && docker compose up -d`）。案内だけで終わらせると、ルールを入れた直後にレポートを出せない。
  立ち上がりに数秒かかるので、起動後にもう一度開けるか確かめる。
- Docker 自体が動いていない・起動に失敗したときは、そこで止めてユーザーへ伝える（勝手に Docker を入れたり設定を変えたりしない）。
- 成果物ビューア（`/d/…`）を使うなら、`docker-compose.yml` の `volumes` に読みたいリポジトリを `:ro` で足す必要がある。
  既に書いてある行がこのマシンに無いパスを指していることもある。**勝手に消さず**、該当する行を見せて確認する。

## 気をつけること

- 書き込む先が違えば別々に入れられる。全体に効かせたあと特定リポジトリにも入れる、といった重複は無駄なので、
  既にどこかで効いているなら「上の階層で既に入っている」ことを先に伝える。
- 本文は report-hub 単体で完結する内容にしてある。タスク管理ツール（WBS など）の運用は含まれない。
  それも要るなら別のルールとして、区画の外に書く（区画内に書くと次のセットアップで消える）。
- `link` で入れたときは、**repo を消したり移したりするとルールが読めなくなる**。移したなら入れ直す（読み込み先のパスが変わるため）。
- スキル自体がまだ入っていないマシンでは、`python3 <report-hub>/bin/setup-claudemd.py install-skill --yes` で
  `~/.claude/skills` から repo 内の実体を参照させる。実体は repo 側に残るので `git pull` でスキルも新しくなる。
